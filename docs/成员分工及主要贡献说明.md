## 3. A：OS 移植与 sched_ext 调度

A 的主要模块是 OS 移植和 sched_ext 调度支持，并提供绑核、隔离和 V 状态感知调度的思路。V 状态切换的 bpf 追踪与 B 共同完成，开销量化与 C 共同完成。

### 3.1 OS 移植

在 Milk-V Jupiter 上整理可用系统并完成移植，使后续 bpftrace 与 sched_ext 能在真实 RVV 硬件上运行。

| 材料 | 内容 |
|------|------|
| `docs/setup/OS调研.md` | openEuler、openKylin、openHarmony、Irradium 等镜像与内核情况 |
| `docs/setup/OS移植方法.md` | Irradium 的 U-Boot/内核与 openEuler rootfs 的移植步骤，以及开启 sched_ext 所需的内核配置 |

### 3.2 sched_ext 调度支持

调度思路由 A 提出并实现为 `vec_affine_sched`：用 uprobe 识别 `ggml_compute_forward_mul_mat` 推理线程，将推理线程限制在 CPU 0–3，普通任务隔离到 CPU 4–7，推理线程使用更长的时间片。

| 材料 | 内容 |
|------|------|
| `src/scheduler/vec_affine_sched.bpf.c` | 内核态 sched_ext 回调：选核、入队、派发、时间片 |
| `src/scheduler/vec_affine_sched.c` | 用户态加载、uprobe 附着与统计读取 |
| `src/scheduler/自定义调度.md` | 痛点、设计目标和策略说明 |
| `src/scheduler/README.md` | 编译、运行和已集成的调度方法 |
| `tests/sched_ext/` | CFS 与 sched_ext、正常负载与高负载的对比结果 |

## 4. B：绑核隔离、量化对比与不同负载测试

B 的主要模块是 CPU 绑核、核心隔离、量化对比和不同负载测试。板卡选型、x86 对照和 llama-server `-Cr`/`-Crb` 修复也由 B 完成。bpf 追踪与 A 共同完成。

### 4.1 选型与跨平台调研

| 材料 | 内容 |
|------|------|
| `docs/setup/板卡选型.md` | 板卡对比与选型 |
| `docs/scheduler/RISC-V名词解析与调度概述.md` | hart、V 状态、上下文切换和向量寄存器保存/恢复 |
| `docs/x86-vstate/x86架构下的_V状态_.md` | x86 XSAVE 向量状态与 RVV V 状态的对照，以及向量状态保存的判定口径 |

量化对比由 B 完成，记录在 `docs/tracker/量化相关脚本/量化相关脚本.md` 的 RISC-V / x86 分组中，并与 `docs/x86-vstate/x86架构下的_V状态_.md` 的判定方法对应。

### 4.2 bpf 追踪

与 A 共同完成。B 完成跟踪方案调研和 save/restore 探测脚本。

| 材料 | 内容 |
|------|------|
| `docs/tracker/bpftrace使用调研.md` | `riscv_v_vstate_save` 调用路径，以及不依赖未导出符号的追踪方法 |
| `src/tracker/vstate_trace.bt` | 全局 V 状态 save/restore 统计 |
| `src/tracker/vstate_trace_cpu.bt` | 按 CPU、进程和线程统计，用于检查绑核后非目标核上的 V 状态切换 |

### 4.3 绑核、隔离与不同负载测试

调度思路由 A 提供。B 实现并测试 CPU 绑定和核心隔离，覆盖 `taskset`、cgroup cpuset、`partition-root`、systemd-scope，以及配合 `chrt` 的 `SCHED_BATCH` / `SCHED_FIFO`。

| 材料 | 内容 |
|------|------|
| `docs/tracker/CPU_affinity_cgroup.md` | affinity 与 cpuset 的设置方法 |
| `docs/llama-server-cr-fix/-Cr_-Crb 无效的解决方案.md` | llama-server 中 `-Cr`/`-Crb` 未传入线程池的原因，以及在 `load_model` 中补挂带亲和性线程池的改法 |
| `src/benchmark/bench_runner.py` | 单组配置下轮换绑核/调度方法，采集 TPS、TTFT、P95 和 V-state |
| `src/benchmark/bench_runner_all.py` | 按多组配置批量执行上述方法 |
| `src/benchmark/README_bench_runner.md` | 运行器配置与方法顺序 |
| `tests/test/` | group1–group10 的方法对比结果 |

不同负载测试由 B 完成。`tests/test/README.md` 中十组配置变化模型规模、线程数、绑定核心、prompt 长度、输出长度和并发，每种方法重复 3 次。

## 5. C：自动化评测与 llama 调度调研

C 的主要模块是自动化评测和 llama-server 调度调研，并完成量化测试与连续批处理测试。V 状态开销量化与 A 共同完成。

### 5.1 调度调研

| 材料 | 内容 |
|------|------|
| `docs/scheduler/CFS调度.md` | CFS 的 vruntime 与公平调度，及其对推理线程抢占的影响 |
| `docs/scheduler/其他调度策略.md` | `SCHED_FIFO`、`SCHED_RR`、`SCHED_BATCH` 与 CFS 的差异 |
| `docs/scheduler/llama-server请求调度与PD线程级优化分析.md` | slot 状态机、`server_batch` / `llama_ubatch`、`-t`/`-tb` 的选择条件 |
| `docs/scheduler/figures/llama_server_slot_state_machine.drawio` | slot 状态机图 |

### 5.2 量化测试与自动化测试

量化测试和自动化测试由 C 完成。`benchmark_llama.py` 支持 QEMU、本机和远程板卡，并在远程模式下自动启停 llama-server，输出轮次汇总和逐请求结果。

| 材料 | 内容 |
|------|------|
| `src/benchmark/benchmark_llama.py` | 普通 benchmark 与自动化实验矩阵 |
| `docs/benchmark/性能评测指南.md` | 指标口径、控制变量、矩阵参数和结果字段 |
| `tests/rvv/` | 1B/3B/8B 模型规模实验，以及 3B 在 p2/p4/p8/p16 下的并发扫描 |
| `tests/README.md` | 上述结果与 WSL 基线的索引 |

实验矩阵固定每 slot context、线程数、prompt 和 cache 策略，分别只改变模型规模或 `--parallel`。V-state 与吞吐、延迟在同一轮请求上统计，对应 `tests/rvv/*_Summary_VState.csv`。这部分开销结果与 A 共同完成。

### 5.3 连续批处理测试

连续批处理测试由 C 完成。自动化矩阵启动的 llama-server 带有 `--cont-batching`。请求如何进入同一 batch、以及并发 Decode 时 `-t` 与 `-tb` 的实际选择，写在 `docs/scheduler/llama-server请求调度与PD线程级优化分析.md`；对应测试结果在 `tests/rvv/`。
