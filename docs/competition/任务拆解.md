### 2. 量化分析工具（10 分）

**目标**：用 eBPF/kprobe 观测 `riscv_vstate_save`，定量回答"V 状态切换到底开销多大"。

| 任务 | 交付物 | 负责人 |
|------|--------|--------|
| kprobe 挂载 `riscv_vstate_save`，统计调用频次、每次耗时、dirty V 被抢占事件 | eBPF 插桩脚本 | @汪坤 |
| 建立量化表格：并发数 × 模型规模 × TPS/平均延迟/P95 TTFT/V 状态切换开销 | 表格数据 | @陈子轩 |

---

### 3. 调度优化实现（15 分）

**目标**：减少 V 状态保存/恢复频率 → 尾延迟改善（吞吐允许略降）。

四种可选方案，从易到难：

| 方案 | 难度 | 预计效果 | 负责人 |
|------|------|---------|--------|
| **A. CPU affinity**：`taskset` / `pthread_setaffinity_np` 绑核 | 入门 | 防止线程迁移，减少不必要的 V 状态切换 | @汪坤 |
| **B. llama.cpp 内置绑核**：`cpu-mask` / `cpu-range` / `-t` / `-tb` | 入门 | 零代码改动的快速验证 | @陈子轩 |
| **C. sched_ext (BPF)**：可扩展调度框架实现 V 状态感知调度 | 进阶 | 最灵活的调度策略定制 | @郭恒 |
| **D. sched_setattr/affinity**：对持有 dirty V 的线程进行调度提示和放置优化 | 进阶 | 细粒度控制，结合内核接口 | @陈子轩 @汪坤 |

> 策略：至少完成 **A + B** 保底，**C 或 D** 选一个冲击。

---

### 4. 性能评测（10 分）

**目标**：定量对比优化前后的效果。

| 要求 | 说明 |
|------|------|
| 基准 | llama.cpp server 模式 |
| 指标 | TPS（吞吐）、平均 TTFT、P95 TTFT、V 状态切换开销 |
| 并发 | 2、4、8 并发 |
| 重复 | 每组 ≥ 3 次，报告均值与标准差 |
| 控制变量 | 相同模型 / 量化 / `--threads` / 输入长度分布 |
| 频率策略 | CPU governor 固定为 `performance` |
| 模型 | Llama-3.2-1B/3B Q4_K_M（≤3B 参数量） |

**负责人**：@陈子轩

## 三、可选完成项（特色创新方向）

> 对应技术报告「特色创新」10 分，建议从中选 1-2 个深挖。

1. **用户态-内核调度提示接口设计** — 探索让用户态提示内核"此线程持有 dirty V，别抢"
