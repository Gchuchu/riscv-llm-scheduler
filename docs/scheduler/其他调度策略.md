# 其他调度策略分析

## SCHED_FIFO（先入先出）

- 一旦任务开始运行，就一直跑，直到主动让出（sleep、I/O）或被更高优先级的 FIFO 任务抢占。
- 矩阵乘法任务若能设置最高优先级（99），一进来就能跑完，不会被中断。
- **优点**：理论上效果最好，V 状态切换开销最低。
- **缺点**：其他进程会完全饿死，实际生产环境不可用。

## SCHED_RR（轮转）

- 不会被普通进程抢占，但相同优先级的任务会轮转执行（消耗完时间片就切换）。
- 时间片较大时，V 寄存器保存开销显著低于 CFS。
- **缺点**：如果优先级设置高了，普通任务仍会被饿死。

## SCHED_BATCH

- 与 CFS 属于同一个调度类（fair scheduling class）。
- 被打断的频率没有 CFS 那么高，但改善幅度有限——只是数值上的不同，机制与 CFS 相同。

## SCHED_IDLE

- 以极低优先级运行作业（甚至低于 SCHED_OTHER/BATCH 策略下 nice=+19 的优先级）。
- 只跑优先级低的进程，效果不如 CFS——CPU 只在空闲时才跑推理。

## SCHED_DEADLINE

- 三个核心参数：

```c
struct sched_attr {
    runtime;   // 每次运行所需时间
    deadline;  // 必须在 deadline 前完成
    period;    // 任务每 period 时间出现一次
};
```

- 例如推理 `runtime = 5ms, period = 8ms`，内核保证 8ms 内有 5ms 是推理线程在运行。
- **优势**：几个调度策略中最平衡的，能同时保证推理线程的 CPU 时间和系统整体公平性。
- **劣势**：需要费很大力气调参才能得到最佳效果。

## 总结

| 策略 | 切换开销 | 公平性 | 适用场景 |
|------|---------|--------|---------|
| CFS | 高（频繁切换） | 最佳 | 通用场景 |
| FIFO | 最低 | 最差（饿死其他进程） | 实时任务 |
| RR | 低 | 差 | 同优先级实时任务 |
| BATCH | 中 | 较好 | 批处理 |
| DEADLINE | 可控 | 好 | 有确定性需求 |
