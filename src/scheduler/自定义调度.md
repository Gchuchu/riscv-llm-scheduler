### 核心痛点

在 RISC-V 异构多核处理器架构中，通常会存在计算能力与指令集扩展（如 Vector 向量扩展）不相同的核心组合。例如，系统包含 4 个配备高性能向量计算单元的 AI/高性能核心（CPU 0~3）以及 4 个低功耗/通用核心（CPU 4~7）。在运行大语言模型如基于 llama.cpp的高负载推理任务时，系统面临以下核心调度痛点：
1. **Linux原生调度器的拓扑盲目性**：  
    Linux 原生 CFS 调度器侧重于 CPU 之间的全局负载均衡，缺乏对异构向量计算单元物理分布的深度感知。在多线程并行推理过程中，原生调度器易将密集计算的 推理 线程调度至低功耗核心（CPU 4~7），导致计算瓶颈。
2. **上下文切换与 Cache 频繁失效**：  
    LLM 矩阵乘法属于典型的计算密集型与内存带宽敏感型任务。若计算线程频繁被普通系统任务抢占或跨核迁移，将引发L1/L2 Cache 失效与 TLB 刷新开销，导致推理吞吐量大幅下降、首 Token 延迟波动。
3. **推理线程与通用任务混跑干扰**：  
    LLM 进程的主线程通常仅负责网络 I/O、命令行交互或任务分发，而真正的向量计算由子线程完成。若将主线程或通用后台任务误判并绑定至 AI 计算核心，会挤占宝贵的向量计算资源。并引发向量切换的寄存器保存开销。
### 调度方案设计目标

为解决上述痛点，本项目设计并实现了基于 eBPF sched_ext 框架的自定义调度器 vec_affine_sched，其核心设计目标如下：
1. **物理级异构硬隔离**：实现线程级的精准识别，将 LLM 密集计算的推理线程**强绑定**在 AI 计算核心（CPU 0~3）；将主线程、通用后台任务与系统进程**隔离**在通用核心（CPU 4~7），实现物理算力的绝对隔离。
2. **Cache 亲和性**：设计原核空闲优先选核。唤醒推理线程时，优先检测并回归其上次运行的 CPU，极大提升 Cache 命中率并降低 TLB 刷洗开销。
3. **长计算时间片保护**：为推理线程赋予 30ms 的超长调度时间片，减少运行期的非必要抢占；同时在唤醒入队时赋予队列首部优先权。

## sched_ext 框架支持与核心工作原理
sched_ext(SCX)是 Linux 内核引入的一种允许通过 eBPF 动态扩展内核调度策略的 Subsystem。
需要额外开启一下配置项
```bash
CONFIG_BPF=y
CONFIG_SCHED_CLASS_EXT=y
CONFIG_BPF_SYSCALL=y
CONFIG_BPF_JIT=y
CONFIG_DEBUG_INFO_BTF=y
CONFIG_BPF_JIT_ALWAYS_ON=y
CONFIG_BPF_JIT_DEFAULT_ON=y
```
它在内核 Core Scheduler 中暴露了一组 struct sched_ext_ops 接口，BPF 程序实现这些回调接口即可接管系统的调度行为。
#### 机制解析：
- **DSQ（Dispatch Queue）**：SCX 抛弃了传统复杂的红黑树调度队列，引入 DSQ 概念。每个 CPU 默认拥有一个 SCX_DSQ_LOCAL 物理队列，此外可由 BPF 程序通过 scx_bpf_create_dsq() 创建自定义的全局或组共享 DSQ。
- **select_cpu 阶段**：任务准备被唤醒时调用，用于探查空闲 CPU。若返回特定 CPU，内核将尽量在此 CPU 触发后续流程。
- **enqueue 阶段**：任务确定入队时调用，BPF 程序可通过 scx_bpf_dsq_insert() 决定将任务插入 Local DSQ 还是 Shared DSQ，同时注入执行时间片）。
- **dispatch 阶段**：当 CPU 的 Local DSQ 为空时调用，用于从 Shared DSQ 转移任务到当前 CPU 准备执行。

## 分层架构设计
vec_affine_sched 采用了典型的**内核态 eBPF 调度引擎 + 用户态控制遥测进程**的双层架构，如图所示，主要分为三部分：
1. **用户态 Loader**：负责加载并校验 BPF 字节码、附着 struct_ops 调度器、下发目标 PID 配置、维护位于 /sys/fs/bpf/vecsched/stats 的 BPF Map Pin 文件，并实时读取聚合 Per-CPU 统计数据。
2. **BPF Map 数据交互层**：config_map 用于同步目标 TGID；stats 收集各类选核与队列计数；task_ctx_map 记录任务级别的上下文属性。
3. **内核态 eBPF 调度引擎**：挂载至 sched_ext 的核心 Hook 节点，截获任务的 CPU 选择、入队与派发流程，按算力拓扑进行分流。
### vec_affine 核心调度策略设计
vec_affine 调度策略专为 RISC-V 异构拓扑与大模型推理特性打造，核心逻辑分为以下四个方面：
#### 1. 任务身份识别
调度器需精准区分“内核线程”、“普通系统任务”、“LLM 主线程”和“LLM推理线程”：
- **过滤特权与受限任务**：通过 p->flags & PF_KTHREAD 以及 p->nr_cpus_allowed == 1 过滤内核线程与已绑定 CPU 亲和性的任务，交由内核默认机制 scx_bpf_select_cpu_dfl() 处理。
- **LLM 进程识别**：首先读取 config_map。若已设置 TGID 则直接比对；若未设置，读取 p->comm，匹配llama前缀。匹配成功后自动更新 config_map 完成 TGID 绑定。
- **推理线程识别**：当 is_llama_process(p) == true 且满足 p->pid != p->tgid（即子线程）时，才判定为计算推理线程。
#### 2. 异构核心硬隔离分配
- **AI Worker 策略**：完全锁定在 **CPU 0 ~ 3** 运行。禁止推理线程溢出到 CPU 4 ~ 7。
- **Other Task 策略**：将主线程及所有普通任务隔离在 **CPU 4 ~ 7** 运行，屏蔽 CPU 0 ~ 3 的调度逻辑。
#### 3.  Cache 亲和性绑定
以 AI Worker 任务选择 CPU 为例，算法按如下三级优先级探查：
1. **优先在原核心执行**：若上次运行的 prev_cpu 属于 CPU 0~3，且通过 scx_bpf_test_and_clear_cpu_idle(prev_cpu) 证实其刚好空闲，直接返回 prev_cpu。
2. **空闲核心其次**：若原核忙，按顺序循环探查 CPU 0~3 中是否有其他空闲 CPU，若有则抢占该空闲核。
3. **兜底等待**：若 CPU 0~3 全忙，若 prev_cpu 在 0~3 范围内则退回 prev_cpu 排队，否则投递至 CPU 0~3 中的某一核心。
#### 4. 差异化时间片与队列优先级
- **推理线程**：赋予 SLICE_INFER_NS(20ms)时间片，直接插入当前 CPU 的 SCX_DSQ_LOCAL 队列；若是唤醒状态，附加 SCX_ENQ_HEAD 标志，确保其插队至 Local DSQ 头部立即执行。保证推离线程的优先级。
- **普通任务**：赋予 SLICE_DEFAULT_NS(4ms)时间片，统一推入 SHARED_DSQ 共享队列，由 CPU 4~7 在 dispatch 阶段通过竞争拉取执行。
### 用户态加载与监控程序实现 
用户态程序基于 libbpf 构建，负责调度器的完整生命周期管控。
#### 关键实现模块：
1. **BPF Skeleton 附着与参数注入**：  
    通过 vec_affine_sched_bpf__open_and_load() 和 vec_affine_sched_bpf__attach() 将结构体 vec_affine_ops 挂载至内核。若用户指定了` -p <PID> `参数，则直接调用 bpf_map_update_elem 更新 config_map。
2. **BPF Map Pinning 与路径管理**：  
    创建 /sys/fs/bpf/vecsched 目录，将 Per-CPU stats Map Pin至文件系统，支持外部工具（如 bpftool）离线观测。
3. **Per-CPU 数据读取**：  
    使用 libbpf_num_possible_cpus() 获取物理 CPU 数量，分配内存并调用 bpf_map_lookup_elem 循环累加所有 CPU 的计数器，格式化输出定时指标。
4. **信号捕捉与卸载**：  
    捕获 SIGINT / SIGTERM 信号。在程序退出时显式调用 vec_affine_sched_bpf__detach() 与 bpf_map__unpin()，内核将自动销毁结构体操作集并平滑回退至原生 CFS 调度器，保障系统稳定性。

### 4.2 策略优势与适用场景边界

#### 方案核心优势：
1. **无侵入与动态部署**：无需重新编译内核，无需修改应用代码，通过 eBPF 结构体操作集动态加载，支持在线升级。
2. **安全**：BPF 字节码由内核 Verification 严格校验，杜绝死锁与空指针访问；即使 BPF 程序异常崩溃，内核 SCX 框架保证系统安全降级回退。
3. **缓存利用**：将轻量级选核与 Prev-CPU Idle 检测移至内核唤醒的最前端，实现了 L1/L2 Cache 保护。
#### 适用场景边界与限制条件：
- **拓扑强依赖性**：当前 vec_affine_sched 内部硬编码了 8 核心拓扑结构（CPU 0~3 为 AI 核，CPU 4~7 为普通核）。若运行于其他 CPU 拓扑（如 4 核或 16 核系统），需要修改内核态常数并重新编译。
- **workload 类型限定**：本调度策略专为计算密集型/长周期批处理（如 LLM 推理、矩阵运算）优化。若应用于高频 I/O 交互、微秒级响应的网络服务，长时间片策略可能导致响应时延增加。
